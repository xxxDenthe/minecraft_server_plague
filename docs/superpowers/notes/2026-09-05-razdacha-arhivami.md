# Раздача пака архивами: порядок работы

**Дата:** 2026-09-05
**Относится к:** подсистема 6 (лаунчер)
**Отменяет:** порядок выкладки из `2026-09-03-razdacha-paka-cherez-releases.md`
**Устройство:** спек `2026-09-05-razdacha-paka-arhivami-design.md`

## Что изменилось

Было: около трёхсот ассетов в релизе, по одному на файл, с именами вида
`mods__create-6.0.10.jar`. Стало: один zip на игровую папку.

```
pack.json              манифест
mods.zip               233 МБ, 92 мода
config.zip
defaultconfigs.zip
kubejs.zip
resourcepacks.zip
shaderpacks.zip
```

Заодно закрылся вопрос лимита запросов, висевший в старой заметке.
Первая установка игрока — семь запросов вместо трёхсот, и потолок
в 5000 в час на общий токен перестал быть узким местом.

## Настройка выкладки, один раз

Создать `launcher/publish.json` — файл не версионируется, в нём токен:

```json
{
  "repo": "xxxDenthe/minecraft_server_plague",
  "tag": "pack",
  "token": "github_pat_... с правом Contents: Read and write",
  "dir": "pack-build",
  "server": "хост:25565",
  "max-ram": "6144"
}
```

Релиз заранее создавать **не нужно**: скрипт создаёт его сам, если
релиза с таким тегом нет. Это была половина ручной возни.

## Выкладка

```bash
cd launcher
node tools/publish-pack.js --dry-run   # что соберётся, ничего не грузя
npm run publish                        # собрать и выложить
```

Ключи командной строки перебивают `publish.json` — удобно для пробного
тега: `node tools/publish-pack.js --tag pack-test`.

Повторный запуск заливает только изменившиеся папки. Правка одного
конфига — это `config.zip` на пару мегабайт, а не 233 МБ модов.

## Сборка лаунчера не изменилась

```bash
npm run configure -- --repo xxxDenthe/minecraft_server_plague --tag pack --token <токен только на чтение>
npm run dist
```

Второй токен, только на чтение, по-прежнему обязателен: у токена
выкладки есть право стереть релиз.

## Живые замеры

92 настоящих мода, 261 МБ на диске, машина владельца:

| Шаг | Время |
|---|---|
| Сжать `mods.zip` | 4,7 с |
| Размер архива | 233 МБ (сжатие 11%) |
| Распаковать | 0,9 с |

Все 92 джарника после круга «сжать — распаковать» совпали побайтово.
Восемнадцать имён с `+` уцелели: внутри zip GitHub имена не трогает,
и старая беда с `curios-neoforge-9.5.1+1.21.1.jar` больше не может
случиться в принципе.

## Что теперь на диске у игрока

`<инстанс>/.lmpc-pack.json` — что установлено: хеш каждого архива
и список распакованных файлов. Лаунчер сверяется с ним, а не считает
хеши 262 МБ на каждом запуске.

Если игрок удалит мод руками, файл из списка пропадёт, и лаунчер
переставит папку молча. Битый, но существующий файл лаунчер не поймает
— это поймает краш клиента. Осознанно: ловить порчу пришлось бы
хешированием всего пака при каждом старте.

Файл лежит в корне инстанса, вне управляемых папок, и внесён
в `PROTECTED`. Стереть его руками безопасно: следующий запуск просто
переустановит пак целиком.

## Чего стоит выбор

Поменялся один мод — игроки качают `mods.zip` целиком, 233 МБ, около
двух минут. Раньше качали бы один джарник. Это сознательная плата
за читаемую страницу релиза; моды между сессиями меняются редко,
а конфиги лежат в своём маленьком архиве.

## Что удалено

`tools/build-manifest.js` и команда `npm run manifest`. Скрипт собирал
манифест старого образца, с `files` вместо `archives`, и после смены
формата падал бы на собственной валидации. Держали его «на случай,
если раздача переедет на свой сервер» — случай не наступил, а
переписывать мёртвый код под новый формат смысла нет.

## Если понадобится откатиться

Старый способ жив в истории: коммит до `Раздача пака архивами`.
Возвращать его целиком смысла нет — проще добавить в манифест
второй тип записи, но такой нужды пока не возникало.
