# Лаунчер: интерфейс LMPC

**Дата:** 2026-09-03
**Относится к:** подсистема 6 (лаунчер)
**Отменяет:** прежний визуал лаунчера («Чума», стеклянная карточка, потом
мёртвый город с фиолетовым акцентом)

Владелец дал развёрнутый бриф: сервер называется **LMPC**, интерфейс —
средневековый, тёмное фэнтези без хоррора, заражённый гибнущий мир,
камень, туман, холодный свет. Готовый пиксельный логотип
`D:\TEXTURES\minecraft_title.png` (скопирован в
`launcher/src/renderer/assets/lmpc-logo.png`).

## Решения

- **Язык интерфейса — русский.** Шрифт — **Segoe UI** (системный,
  скачивать нечем, строгий CSP). Пиксельным остаётся только логотип.
- **Палитра — холодный камень:** чёрный, угольный, серо-синий, бледный
  камень. **Фиолетового нет** (в отличие от внутриигровой палитры мода):
  один приглушённый стально-синий акцент `#728b99`, очень скупо —
  фокус, активный прогресс. Токены в шапке `style.css`.
- **Окно 1280×720, фиксированное, без ресайза мышью.** Fullscreen по
  F11 и из настроек — окно и клавиша синхронизированы через события
  `window:fullscreen`. Интерфейс центрируется и не растягивается.
- **Приложение переименовано в LMPC целиком:** `appId gg.lmpc.launcher`,
  productName «LMPC Launcher», артефакт `LMPC-Launcher-0.1.0.exe`, папка
  игрока `%APPDATA%\LMPC`, переменная `LMPC_LAUNCHER_ROOT`. Старые
  установки (был только тест на стороннем ПК) осиротеют — переименовано
  сейчас, пока сессия не началась.

## Архитектура интерфейса

Стек не менялся: Electron + ванильные ES-модули в renderer, без
сборщика, без фреймворка. Renderer разбит на модули по одной
ответственности:

```
main.js        оболочка: хранилище, роутинг экранов, вся связь с main
state.js       перечисление состояний + крошечный store (subscribe/set)
ui.js          el()/icon()/clear() — сборка DOM без innerHTML
background.js  слоёная процедурная сцена + частицы
header.js      логотип + Discord + Настройки/Назад + fullscreen
home.js        главный экран
settings.js    экран настроек по категориям
progress.js    полоса состояния, одна на все стадии
news.js        новости — заглушка со сменным источником
```

Процедурный фон (`background.js`, без картинок): градиент неба,
холодный свет на горизонте, дальние холмы, средневековые руины
(куртинная стена с зубцами, надвратная башня с аркой, обвалившиеся
башни), мёртвый лес по краям, слои тумана (CSS), редкие частицы пепла
(canvas, замирают при `prefers-reduced-motion`), виньетка, зерно
(SVG `feTurbulence`). Всё помечено `ponytail:` — если появится
настоящий арт, он заменит `.bg-scene`, остальные слои остаются.

## Что подключено, а что заготовка

**Работает:** запуск игры, никнейм, min/max RAM (два ползунка, пишутся
в конфиг и уходят в `-Xms/-Xmx`), аргументы JVM (добавляются к
аргументам пака), открыть папку игры/логов, fullscreen окна, кнопка
Discord (`https://discord.gg/7GKFA9zvX5`), полоса прогресса на всех
стадиях (`STAGES` → `State`), состояние ошибки со спокойным текстом,
«Повторить» и раскрывающимися техническими деталями.

**Заготовка / disabled (без ложной функциональности):**

- **Java** — жёстко зашита встроенная JRE 21; «Выбрать другую» и путь
  выключены с пометкой «Появится в следующей версии»;
- **разрешение игры и полный экран в игре** — аргументы с `features`
  лаунчер намеренно отбрасывает (`selectArguments`), поля выключены;
- **News** — источник `loadNews()` возвращает пустой список, показывает
  спокойную заглушку; заменить на fetch(JSON/API) — и больше ничего;
- **«Проверить обновления»** — кнопка выключена. Ручного обновлятора с
  диффом нет; пак и так сверяется и дособирается при каждом запуске,
  об этом сказано под кнопкой.

## Что не проверено глазами

Активные стадии прогресса (CHECKING/LOADING/LAUNCHING), состояние
ошибки и масштабирование в fullscreen написаны по спецификации, но в
работе не проверялись — для этого нужен токен раздачи и живая сеть.
