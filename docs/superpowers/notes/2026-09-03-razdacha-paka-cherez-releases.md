# Раздача пака через GitHub Releases: как это делается и почему так

**Дата:** 2026-09-03
**Относится к:** подсистема 6 (лаунчер), спек раздел 12, план задача 13

## Три особенности GitHub, из-за которых наивный способ не работает

Наивный способ — залить файлы в релиз и написать в манифесте адреса
вида `https://github.com/.../releases/download/pack-1/create.jar`.
Он ломается сразу в трёх местах.

**1. У приватного релиза прямые адреса не работают.** `browser_download_url`
рассчитан на сессию в браузере. Программе доступен только API:

```
GET https://api.github.com/repos/{owner}/{repo}/releases/assets/{id}
Authorization: Bearer <токен>
Accept: application/octet-stream
```

Без `Accept: application/octet-stream` придёт JSON с описанием ассета,
а не файл. Значит, в манифесте должны стоять **id ассетов**.

**2. GitHub переименовывает ассеты.** Спецсимволы в именах заменяются;
в частности, `+` превращается в `.`, потому что незакодированный плюс
в адресе загрузки читается как пробел. **У 21 мода нашего пака `+`
в имени** — `curios-neoforge-9.5.1+1.21.1.jar`,
`lithium-neoforge-0.15.4+mc1.21.1.jar` и другие. Опираться на имена
ассетов нельзя.

**3. Список ассетов плоский.** Папок в релизе нет, а нам нужны
`mods/x.jar` и `config/create/common.toml`. Путь обязан жить
в манифесте.

## Что из этого следует

Манифест собирается **после** загрузки, из ответов API: id ассета
известен только тогда. Поэтому `tools/publish-pack.js` делает загрузку
и сборку манифеста одним проходом, а `tools/build-manifest.js` остаётся
для отладки и для случая, если раздача однажды переедет на свой сервер.

Имя ассета — путь с `/`, заменёнными на `__`
(`config__create__common.toml`). Лаунчеру это не нужно, он берёт путь
из манифеста; это нужно человеку, который откроет релиз глазами.

Сам манифест лежит в том же релизе ассетом `pack.json`. Лаунчер ищет
его через **тег**, а не по прямому адресу: при перезаливке id ассета
меняется, а тег остаётся. Отсюда два запроса на старте — тег, потом
файл. В репозитории манифест не хранится намеренно: пуш требует
браузерной авторизации, а выкладывать правку посреди сессии нужно
за минуту.

## Порядок действий

**1. Создать токен.** GitHub → Settings → Developer settings →
Personal access tokens → Fine-grained tokens.

- Repository access: только `minecraft_server_plague`
- Permissions → Repository permissions → **Contents: Read and write**
- Срок: сессия идёт четыре дня, хватит 30 дней

Этот токен — для выкладывания. Игрокам он не достаётся.

**2. Создать релиз.** В репозитории → Releases → Draft a new release.

- Тег: `pack` — **один на всё время**, не `pack-1`, `pack-2`.
  Версия пака живёт числом внутри манифеста, а тег служит стабильным
  входом для лаунчера
- Заголовок любой, описание не нужно
- Publish release (репозиторий приватный, релиз тоже виден только своим)

**3. Собрать папку пака.** `launcher/pack-build/` — точная копия того,
что должно лежать в игровой папке:

```
pack-build/
  mods/            99 джарников из mods/, включая plaguecore-0.1.0.jar
  config/          конфиги после настройки
  defaultconfigs/
  kubejs/
  resourcepacks/
  shaderpacks/
```

Личные файлы (`options.txt`, `saves/`, `screenshots/`, `logs/`,
`servers.dat`) скрипт отбрасывает сам — они никогда не попадут в пак
и не будут затёрты у игрока.

**4. Проверить, что соберётся, ничего не загружая:**

```bash
cd launcher && node tools/publish-pack.js --repo xxxDenthe/minecraft_server_plague --dry-run
```

**5. Выложить:**

```bash
cd launcher && node tools/publish-pack.js \
  --repo xxxDenthe/minecraft_server_plague \
  --tag pack \
  --token <токен> \
  --server plague.example.net:25565
```

Скрипт зальёт файлы, соберёт манифест с id ассетов, прогонит его через
нашу же валидацию и выложит `pack.json` последним. Повторный запуск
заливает **только изменившееся** — правка баланса посреди сессии
занимает минуту, а не перезаливку трёхсот файлов.

**6. Собрать лаунчер с адресом раздачи.** Второй токен — **только
на чтение** (Contents: Read-only), он попадёт в сборку:

```bash
cd launcher
set PLAGUE_REPO=xxxDenthe/minecraft_server_plague
set PLAGUE_RELEASE_TAG=pack
set PLAGUE_MANIFEST_TOKEN=<токен только на чтение>
npm run dist
```

## Что здесь честно неидеально

**Токен на чтение извлекаем.** Он лежит внутри установщика, и любой,
кто его откроет, достанет токен за минуту. Против случайного человека
защищает, против настойчивого — нет. Для круга из восьми человек этого
достаточно (решение спека, раздел 12). Ротация токена = пересборка
лаунчера.

**Лимит запросов — 5000 в час на токен, а токен у всех общий.**
Первая установка одного игрока — примерно столько запросов, сколько
файлов в паке (сейчас около 110 при паке из одних модов, больше
с конфигами). Восемь человек, ставящих одновременно, укладываются,
но с запасом не большим. Если файлов станет заметно больше тысячи,
конфиги придётся паковать в архив.

**Второй токен обязателен.** Не зашивать в лаунчер тот, которым
выкладываем: у него право на запись, то есть возможность стереть
релиз.

**Релиз должен существовать заранее.** Скрипт его не создаёт: решение
о том, каким будет релиз и репозиторий, — не дело скрипта.
