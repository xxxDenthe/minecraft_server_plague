## 1. Архитектура — решено, не пересматривать

Классы — **отдельный Gradle-мод `lmpc_classes`**, не часть
`plaguecore`. `plaguecore/` — территория владельца, `lmpc_classes/`
(как `launcher/`, `lmpc_gmtools/`, `lmpc_shade/`) — моя. Мост между
модами — только рефлексия (`PlagueBridge.java` здесь ↔
`ClassBridge.java` там), без Gradle-зависимости. Это уже дважды
нарушалось и дважды чинилось в этой же сессии — если тянет
отредактировать файл в `plaguecore/mc/`, это неправильный порыв,
остановиться. Подробности — память `plaguecore-chuzhaya-territoriya`.

`plaguecore` теперь отдаёт официальный `PlagueApi.cure/grantImmunity`
(подсистема 2 закрыта другом 2026-09-05) — `PlagueBridge` рефлексирует
именно на него, не на внутренние поля.

## 2. Состояние: Клирик готов, три класса не начаты

**Клирик (v0.5.2) — полностью играбелен:**
- Кулон (`clerics_pendant`, слот Curios `necklace`) — пассивная защита
  от заразы через мост в `plaguecore`.
- Отвар (`clerics_brew`) — пьёшь сам (гейт на использовании, не на
  крафте) **или** поишь союзника наведением: подходишь вплотную
  (1.5 блока), целишься, держишь ПКМ 3 секунды — прогресс-бар и
  x-ray-обводка (только тебе видна, рефлексия на `setSharedFlag`,
  не сетевая). Сервер сам всё перепроверяет на завершении канала.
- Алтарь призвания (блок) — выбор/смена класса, кулдаун 30 мин,
  мастерство при смене срезается до 30%, не обнуляется.
- Гримуар (предмет `class_codex`, выдаётся сам при первом выборе
  класса) — экран-разворот книги (не ванильная книга), фон —
  присланная владельцем картинка, четыре вкладки (роль+лор+мастерство
  у своего класса). Лор — **черновой текст, не финальный**, я его
  написал сам чтобы не было пусто — это не моя территория, лор пишет
  владелец.

**Не сделано у Клирика (сознательно отложено):**
- Мастерство ничем не растёт — поле есть, срезается при смене, нет
  триггера роста. Логичный триггер — успешное лечение.
- Реагент (`plague_bloom`→`cleansing_agent`) не заблокирован по
  классу на крафте — по спеку должен быть Клирик-эксклюзивом
  («обработка»), отложено: пока нет ни одного потребителя реагента
  (Очиститель, курильница), незачем гейтить.

**Кузнец, Фермер, Летописец — только роли в спеке, ноль кода.**
Кузнец готов начинать первым — его тиры Очистителя уже описаны
в `plague-core-design.md`, раздел 10.1 (в `plaguecore`, читать можно,
не трогать).

## 3. Технические заметки, которые сэкономят время

- **Curios: мало объявить тег на предмет.** Слот ещё нужно выдать
  сущности отдельным файлом `data/<namespace>/curios/entities/*.json`
  (`{"entities": ["minecraft:player"], "slots": ["necklace"]}`) —
  без него предмет физически не наденется, хотя тег и регистрация
  `CuriosApi.registerCurio` были правильными. Формат сверен с
  `supplementaries`/`sophisticatedbackpacks`, уже в паке. Наступил
  на эти грабли один раз, обошлось без второго.
- **Curios у нас не мягкая зависимость**, хоть и задумывалась такой:
  `ClericsPendantItem implements ICurioItem` напрямую — без Curios
  JVM не грузит сам класс, падает вся регистрация мода. `required`
  в `neoforge.mods.toml`, не `optional`.
- **Настоящая (не x-ray) модельная обводка сущности требует миксина** —
  `RenderLivingEvent` не даёт точки расширения для второй отрисовки
  той же позы через публичный API. Проект миксинов избегает. Решили
  оставить x-ray, дистанция 1.5 блока и так снимает проблему на
  практике.
- **`GuiGraphics.blit` не тянет источник/назначение независимо** —
  масштаб только через `pose().scale(...)` вокруг вызова.
- **JPG не хранит альфу** — если владелец пришлёт ещё референсов,
  конвертация в PNG с ключеванием почти-чёрного в прозрачность —
  see git history `lmpc_classes` 0.5.2 (PowerShell + `LockBits`,
  быстрее, чем `GetPixel`/`SetPixel` на весь холст).
- **Проверка живьём:** у меня нет доступа к экрану игры — весь UI
  проверяю только по логам (падает/не падает при `runClient`/
  `runServer`, комбинированный тест обоих джарников вместе). Вёрстку,
  цвета, отступы подтверждает только владелец.
- Джарник кладу и в `mods/` (для реальной раздачи), и собираю —
  `cd lmpc_classes && ./gradlew build`, версия в `gradle.properties`
  за каждое весомое изменение.
