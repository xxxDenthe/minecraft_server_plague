# Как ломать голос через API Simple Voice Chat

**Дата:** 2026-09-03
**Нашлось:** вопрос владельца по ходу дизайна материализации
**Статус:** разведка проведена, к реализации — в подсистеме «заражение игрока» (спек 9.5)

Всё ниже проверено по классам самого мода
`mods/voicechat-neoforge-1.21.1-2.6.22.jar` через `javap`, а не по памяти.

## Точка входа

Мод объявляет плагин, voicechat его сам находит:

```java
@ForgeVoicechatPlugin
public class ЧумнойГолос implements VoicechatPlugin {
    public String getPluginId() { return "plaguecore"; }

    public void registerEvents(EventRegistration reg) {
        reg.registerEvent(MicrophonePacketEvent.class, this::наПакетМикрофона);
    }
}
```

`MicrophonePacketEvent` приходит **на сервере**, когда игрок сказал
слово. Через `PacketEvent` доступны `getSenderConnection()`
и `getReceiverConnection()` — то есть известно, чей это голос.

## Как править звук

Ключевое: у пакета есть **сеттер**, поэтому ничего пересылать вручную
не надо — правим пакет на месте, и его получат все слушатели.

```java
MicrophonePacket пакет = event.getPacket();
byte[] opus = пакет.getOpusEncodedData();   // сжатый звук
short[] pcm = декодер.decode(opus);         // 48 кГц, моно, кадр 20 мс = 960 сэмплов
исказить(pcm, стадия);                       // наша обработка
пакет.setOpusEncodedData(кодер.encode(pcm));
```

Декодер и кодер даёт сам API: `VoicechatApi.createDecoder()`
и `createEncoder()`. Opus держит состояние потока, поэтому **на каждого
говорящего свой декодер и кодер**, в `Map<UUID, ...>`, с закрытием
по `PlayerDisconnectedEvent`.

Побочный подарок: двойное сжатие Opus само по себе слегка портит
звук. Нам это на руку.

## Чем именно портить голос

Всё это — арифметика над массивом `short[]`, без единой библиотеки.

| Эффект | Как | На что похоже |
|---|---|---|
| Глухота | однополюсный фильтр низких частот: `y += a * (x - y)` | говорит через тряпку, нос заложен |
| Хрип | мягкое ограничение `tanh(k * x)` плюс шум по огибающей | сорванное горло |
| Дрожь | умножение на синус 4–7 Гц глубиной 0.3–0.6 | озноб, голос трясётся |
| Обрывы | с вероятностью p кадр глушится целиком | связь пропадает, слово теряется |

Раскладка по стадиям заражения игрока:

```
стадии 0–2   не трогаем вообще — обычное общение должно оставаться обычным
стадия 3     глухота + лёгкий хрип
стадия 4     глухота + сильный хрип + дрожь + редкие обрывы
```

## Чего делать не надо

**Понижение тона.** Звучит заманчиво, но кадр обязан остаться ровно
20 мс, а простое замедление меняет длительность. Настоящий сдвиг тона
требует растяжения времени (фазовый вокодер или WSOLA) — это отдельная
серьёзная работа с артефактами и отладкой на живых людях. Связка
«глухота + хрип + дрожь» даёт девять десятых нужного впечатления даром.

**Обработку на клиенте.** `ClientReceiveSoundEvent` даёт готовый
`short[]` через `getRawAudio()`/`setRawAudio()` и на первый взгляд
проще. Но тогда стадию заражения надо синхронизировать на всех
клиентов, и каждый клиент решает сам — а он может решить иначе.
Сервер — одна точка правды.

## Цена

Кадров 50 в секунду на говорящего. Декод и кодирование Opus — доли
миллисекунды на кадр. При восьми игроках, из которых говорят
одновременно один-двое, это доли процента ядра.

Главное: обработка идёт в потоке голосового чата, **не в главном потоке
сервера**. На TPS не влияет вообще.

Ещё дешевле: если стадия ниже третьей, выходим сразу, до декодирования.
То есть пока никто тяжело не болен, плагин не делает ничего.

## Что предстоит уточнить перед реализацией

- Точные координаты maven-артефакта API (репозиторий `maven.maxhenkel.de`,
  версия API не совпадает с версией мода) — **не проверено**
- Зависимость подключать как `compileOnly`, а сам плагин держать
  в отдельном пакете `compat`, чтобы мод работал и без voicechat
- Проверить на живых людях, что стадия 4 остаётся играбельной:
  «почти неразборчиво» из спека легко превратить в «невозможно играть»
