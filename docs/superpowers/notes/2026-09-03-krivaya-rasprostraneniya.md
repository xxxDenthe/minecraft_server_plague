# Кривая распространения не сходится со спеком

**Дата:** 2026-09-03
**Нашлось:** при выполнении плана `2026-09-03-plague-core-foundation.md`, Task 10, шаг 3
**Статус:** требует решения до плана материализации

## Что случилось

План предписывал живую проверку: после `generate 0.1` прогнать
`/plague fastforward 30` и убедиться, что заражено 75–85% мира.
Реальный прогон на сервере дал **30,2%**.

Тест `PhaseTableTest.кривойХватаетНаВосемьдесятПроцентовКТридцатойНочи`
при этом зелёный — он проверяет арифметику бюджетов, а не симуляцию.
Расхождение поймала именно живая проверка, ради чего она в плане и стояла.

## Причина

Бюджет ночи — это потолок, а не гарантия. Заражение расширяется только
по границе очага, и граница растёт как корень из площади, а бюджеты
в спеке 6.2 растут линейно.

Замеры на сетке 63 × 63, один очаг, старт 10%:

```
ночь  1: бюджет  25, заражено   7
ночь 10: бюджет  50, заражено  16
ночь 20: бюджет  95, заражено  27
ночь 30: бюджет 150, заражено  38

итого за 30 ночей: назначено 2735, использовано 759 — 28% бюджета
```

Периметр очага:

```
при 10% мира (397 чанков) фронт — 117 ячеек
при 29% мира (1156 чанков) фронт — 219 ячеек
```

При `base` = 0.04…0.16 и фронте в полторы-две сотни ячеек ночь физически
не может дать 150 новых чанков. Бюджет не ограничивает вообще ничего.

## Внутреннее противоречие спека

Раздел 12.3 задаёт `/plague generate <процент> [очагов]` с числом очагов
**по умолчанию 1–3**. Раздел 6.2 считает бюджеты так, будто мир заполняется
равномерно. Эти два места несовместимы: при 1–3 очагах бюджеты недостижимы
в принципе.

## Что можно сделать

Поднятие `base` работает плохо: даже восьмикратное даёт лишь 77%, потому
что упирается в тот же периметр.

Число очагов решает задачу прямо. Доля мира на ночь 30, среднее по пяти
сидам:

```
очагов   base x1   base x1.5   base x2   base x3   base x4
   1       23.2      28.1       31.2      37.5      43.1
   3       37.2      44.9       50.9      58.5      63.8
   6       46.1      55.4       61.9      68.4      71.3
  10       58.0      67.5       71.3      75.0 *    76.3 *
  16       67.8      74.1       75.9 *    77.3 *    78.1 *
  24       74.3      76.6 *     78.0 *    78.9 *    78.8 *
  32       75.3 *    76.9 *     77.6 *      —         —
  40       77.1 *    78.1 *     78.5 *      —         —

* — попадание в целевой коридор 75–85%
```

Варианты, по возрастанию вмешательства в спек:

1. **32 очага на старте, числа фазовой таблицы не трогаем** — 75,3%.
   Спек 6.2 остаётся дословно как есть, меняется только значение по
   умолчанию в 12.3 (было 1–3).
2. **24 очага и `base` × 1.25** — 75,9%. Мягче по числу очагов,
   но правит фазовую таблицу.
3. **Оставить как есть и сдвинуть цель спека к 30%** — если по ощущениям
   треть заражённого мира к тридцатой ночи это то, что нужно. Тогда
   правится не код, а ожидание в спеке.

Выше 79% кривая не идёт ни при каких множителях: мешают вода и камень
с их низкими множителями местности, а также потолок бюджета.

Решение — игровое, не техническое, поэтому оставлено владельцу.

## Побочная находка

`/plague generate` в текущей реализации требует, чтобы очаги были посажены
заранее через `/plague seed`. Спек 12.3 описывает форму
`generate <процент> [очагов]`, где команда сажает очаги сама. Если выбирается
вариант 1, эту форму имеет смысл реализовать заодно — иначе админу придётся
кликать 32 очага руками.
