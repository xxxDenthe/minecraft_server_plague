# Очистка: обратный проход материализации

**Дата:** 2026-09-05
**Повод:** живая проверка очистителя (`lmpc_classes` 0.7.0) владельцем
**Задето:** `plaguecore` — `Materializer`, `BlockTransforms`, `PlagueGrid`
**Версия:** `plaguecore` 0.1.0 → 0.1.1, `mods/MODLIST.md` поправлен

---

## Что случилось в игре

Очиститель поставлен, вал подведён, при правом клике блок отвечает
«работает». Уровень заражения чанка при этом падает, а блоки в мире
остаются гнилыми. Владелец: «блоки не очищаются, т.е. не становятся
обычными».

## Причина

Материализация была односторонней. `Materializer.поставить` отбрасывал
чанк, если расчётный уровень **не больше** уже отрисованного:

```java
// Обратный проход при очистке — забота подсистемы очистителей,
// здесь только рост.
if (grid.maxLevelAround(i) <= grid.getAppliedSurfaceAt(i)) return false;
```

То есть `PlagueApi.cleanseChunk` честно снимал уровень в сетке, но
никто и никогда не возвращал блоки назад. Обратного прохода не
существовало ни в ядре, ни в моде классов — комментарий отсылал
к подсистеме, которая его так и не написала.

Класс Клирика к делу отношения не имеет: первый тир очистителя по спеку
доступен всем, класс Кузнеца влияет только на силу.

## Решение

Проход стал двусторонним, и живёт это в ядре, а не в блоке очистителя:
любой будущий очиститель — латунный, электрический, курильница — получит
отыгрыш назад даром.

- `PlagueGrid.surfaceOutOfDateAround(index)` — неравенство в обе стороны
  с оглядкой на кайму соседей. Существовавший `surfaceOutOfDateAt`
  сравнивает уровень **своего** чанка и для материализации не годится:
  отрисованное значение берётся по максимуму вокруг, и такой предикат
  залипал бы на «отстаёт» у каждого чанка с заражённым соседом.
- `Materializer.отработатьТик` выбирает направление по знаку разницы:
  цель больше отрисованного — гниём, меньше — лечим.
- `BlockTransforms.restoration` — обратная таблица «наш блок → чем был».

## Границы решения, принятые сознательно

- **Возвращаем только свои блоки.** Подзол и вытоптанные посевы не
  трогаем: подзол растёт в тайге и без чумы, посевы дорастают сами.
  Иначе очистка съедала бы куски настоящего мира.
- **Порода не хранится**, поэтому ствол и листва возвращаются дубовыми.
  Помечено `ponytail:`. Хранить исходный блок — это ещё одна сетка на
  весь мир; заводить, если разноцветный лес после очистки будет резать глаз.
- **Сила внутри столбца назад не понижается**: столбец, который всё ещё
  входит в поражённую долю, остаётся гнилью и не становится подзолом.
  Лечится столбец целиком, когда доля его отпускает.
- **Пещеры не тронуты.** `CaveMaterializer` так и остался односторонним:
  очиститель по спеку 10.1 поверхностный, под землёй своя курильница.

## Чего ждать в игре

Мир очищается не мгновенно и не полностью:

- очиститель работает **раз за ночь** и только при смене номера ночи;
  свою первую ночь после установки он пропускает намеренно, чтобы не
  отрабатывать задним числом за всё прошедшее время;
- уровень снимается **с вероятностью**, а не наверняка;
- правило 10.2 не даёт окопаться: если рядом есть чанк уровня 3 и выше,
  очиститель держит свой чанк на единице и ниже не опускает. В середине
  большого заражённого региона полной чистоты не будет, пока не очищены
  соседи.

Быстрая проверка на дев-сервере: `/plague ночь` прокручивает ночь,
`/plague перерисовать <радиус>` сбрасывает память об отрисовке.
