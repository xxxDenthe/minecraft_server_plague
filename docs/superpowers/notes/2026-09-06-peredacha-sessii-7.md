## Разбор: очиститель «не работает»

Владелец 2026-09-06 поставил очиститель на заражённую землю, проскипал
две ночи и не увидел изменений. **Это ещё не баг.** Прежде чем лезть
в код, исключить три вещи — по коду они все ожидаемые.

1. **Чистится только свой чанк**, 16 × 16 блоков под очистителем.
   Не «местность вокруг». Радиус 3×3 и 5×5 — это верхние тиры,
   которых нет (пункт «Долг помельче»).
2. **Первая ночь после установки пропускается всегда.** При первой
   встрече с миром блок только запоминает номер ночи, чтобы
   не отработать задним числом за всё прошедшее. Две ночи — это
   **одна** реальная попытка.
3. **Шанс за ночь 30 %** (`purifierCleansePower`, теперь 0.30),
   и за удачу снимается **один** уровень. Одна попытка ничего
   не показывает.

Плюс два условия, без которых блок вообще не работает: **вал должен
касаться** одной из шести соседних клеток (не «стоять рядом»),
скорость не ниже 8 об/мин, и внутри должен лежать `cleansing_agent`.

**Диагностика:** щёлкнуть по очистителю пустой рукой — он отвечает
одно из трёх: «нет вращения», «нет реагента», «работает, реагента N,
Кузнец: тир …».

**Проверка наверняка:**

```
/lmpcclasses tune purifierCleansePower 1.0
/plague night        # по одной, с паузой в пару секунд
/plague gui          # карта, посмотреть уровень чанка
```

Ночи по одной — не пачкой. Очиститель сверяет номер ночи раз в секунду,
и `/plague fastforward 10` он увидит как **одно** изменение и отработает
один раз.

Последнее: если **соседний** чанк заражён на 3+, очиститель держит свой
чанк на уровне 1 и ниже не опустит. Это правило «нельзя окопаться»
из спека ядра 10.2, оно живёт внутри `PlagueApi.cleanseChunk`.

## Порядок работы, если забылось

Границы владения: `plaguecore/`, `tools/`, `textures_src/` — владелец;
`launcher/`, `lmpc_classes/`, `lmpc_gmtools/`, `lmpc_shade/` — второй
участник. Запрет на правку `plaguecore` владелец снял 2026-09-05,
но правки туда — минимальные и добавляющие, каждая заметкой.

```bash
git pull --rebase origin main    # перед началом работы
# ... работа, мелкий коммит ...
git pull --rebase origin main    # перед пушем
git push origin main
```

Собранные джарники раскладывать в `mods/` и править версию
в `mods/MODLIST.md` — версии клиента и сервера обязаны совпадать
у всех четырёх наших модов.

Решения записывать в `docs/superpowers/notes/`, а не в переписке:
сессия Claude у каждого своя и чужого разговора не видит.
