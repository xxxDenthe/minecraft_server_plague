# Подсказки предметов в стиле Create (lmpc_classes 0.18.0)

2026-09-07, задача владельца: «у многих предметов из create-аддонов
есть при наведении "Удерживайте [Shift] для сводки", ту же историю надо
добавить и некоторым нашим предметам… всё должно быть как у условного
мода create_copycats. Оранжевый текст и слегка выделенный
жёлто-оранжевый для важных моментов… одна строка с кратким лором и для
чего он нужен в игре. Всё должно быть понятно для игрока,
не для разработчика».

Названы пять предметов: кулон Клирика, гримуар призвания, бутон чумы,
очищающий реагент, курильница.

## Как это сделано

Своего кода на отрисовку нет ни строки, и это главное решение заметки.
Create держит открытый реестр `TooltipModifier.REGISTRY`
(`com.simibubi.create.foundation.item`), а его `ClientEvents` опрашивает
реестр на каждый `ItemTooltipEvent` **для любого предмета, чей бы мод
его туда ни положил** — проверки по пространству имён там нет.
Поэтому весь наш код — это `client/CreateTooltips.java`, пять строк
регистрации на `FMLClientSetupEvent`:

```java
TooltipModifier.REGISTRY.register(предмет,
    new ItemDescription.Modifier(предмет, FontHelper.Palette.STANDARD_CREATE));
```

Дальше Create делает всё сам: читает языковой файл, режет строки по
ширине, рисует «Удерживайте [Shift] для сводки» и раскрывает сводку по
нажатию. Палитра `STANDARD_CREATE` и есть то, что просил владелец, —
оранжевый текст с жёлто-оранжевой подсветкой; ровно её же берут
дополнения вроде `create_copycats`.

Это прямое применение курса create-style
(`2026-09-06-create-style-kurs.md`): механику берём у Create, а не
пишем свою на ванильных хуках. Жёсткая зависимость на Create у мода
уже есть, так что проверок «а вдруг Create нет» не нужно.

## Ключи и формат текста

Create складывает подсказку из ключей вокруг
`item.lmpc_classes.<предмет>.tooltip`:

- `.summary` — абзац: лор одной фразой плюс зачем предмет нужен;
- `.condition1` / `.behaviour1` — пара «когда» и «что делает»,
  дальше по номерам;
- `.control1` / `.action1` — вторая страница по Ctrl, у нас не занята.

Слово, обёрнутое подчёркиваниями (`_вот так_`), Create красит цветом
подсветки. Строку «Удерживайте [Shift] для сводки» переводить не надо:
она приходит из языкового файла самого Create
(`create.tooltip.holdForDescription`), и русский перевод там уже есть.

## О чём написано в сводках

Лор во всех пяти — приземлённый и «промышленный», как требует
`minecraft-plague-lor-prizemlennyj`: вещи не сделаны против чумы,
их под неё **приспособили**. Кулон был аптекарским пробником, реагент
— тепличным средством от плесени, курильница — шахтёрской лампой,
гримуар — рабочей тетрадью артели, бутон — сорняком, который раньше
выпалывали. Тон владелец задал сам примером про очиститель
(«раньше был нужен для экспериментальной системы поливок посевов»).

Дальше в каждой сводке — только то, что игроку правда нужно знать:
кулон надо надеть в слот ожерелья и у Клирика он вдвое сильнее;
гримуар только читают, класс меняют у Алтаря; бутон всходит лишь
у Фермера, но сырьём остаётся для всех; реагент тратится и машиной,
и курильницей; курильница не работает под открытым небом и даёт
чанку тающее сопротивление.

Числа в тексте намеренно округлены («примерно на четверть», «пауза
в несколько секунд»): все они живут в конфиге и в `/lmpcclasses tune`,
и точная цифра в подсказке рассохлась бы при первой же настройке.

## Сторож

`lmpc_classes/tools/check_tooltips.py`. Опечатка в ключе или забытый
перевод ничего не ломают — подсказка молча исчезает, и заметить это
можно только наведясь на предмет в игре. Проверка читает список
подключённых предметов прямо из `CreateTooltips.java` и следит,
что у каждого есть `summary`, что `conditionN` и `behaviourN` идут
парами и что русский с английским знают одни и те же ключи.
