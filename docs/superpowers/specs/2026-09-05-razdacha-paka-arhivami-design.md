# Раздача пака архивами вместо трёхсот ассетов

Ревизия 1 · 2026-09-05 · подсистема: лаунчер

## Задача

Сейчас пак раздаётся через приватный релиз GitHub по одному ассету
на файл: около трёхсот плоских имён вида `mods__create-6.0.10.jar`.
Страница релиза нечитаема, а выкладка требует заранее созданного
релиза и ключей в командной строке.

Меняем две вещи и только их:

1. В релизе становится один архив на игровую папку плюс манифест —
   семь файлов вместо трёхсот.
2. Выкладка идёт одной командой `npm run publish` без аргументов.

Механику установки, запуска, Java, NeoForge и обновления не трогаем.

## Что остаётся как есть

- Раздача — приватный релиз GitHub, тег `pack`, доступ по токену
- Скачивание — через API по id ассета: у приватного релиза
  `browser_download_url` не работает
- Манифест `pack.json` — единственный источник истины о клиенте
- Разделение «planSync считает — applySync делает»
- Список `PROTECTED`: настройки, миры, скриншоты и логи не трогаем

## Состав релиза

```
pack.json              манифест
mods.zip               262 МБ, 93 файла
config.zip
defaultconfigs.zip
kubejs.zip
resourcepacks.zip
shaderpacks.zip
```

Архив собирается только для папки, в которой есть файлы. Пустая папка
архива не получает и в манифесте не появляется.

## Манифест, ревизия 2

Поле `files` заменяется на `archives`. `managedDirs` остаётся: по нему
чистятся папки, для которых архива больше нет.

```json
{
  "packVersion": 5,
  "minecraft": "1.21.1",
  "neoforge": "21.1.249",
  "java": { "major": 21 },
  "launch": { "maxRamMb": 6144, "jvmArgs": ["-XX:+UseG1GC"] },
  "server": { "host": "...", "port": 25565 },
  "managedDirs": ["mods", "config", "defaultconfigs", "kubejs",
                  "resourcepacks", "shaderpacks"],
  "archives": [
    {
      "dir": "mods",
      "sha256": "<хеш самого zip, для проверки скачанного>",
      "contentId": "<отпечаток содержимого, для выкладки>",
      "size": 274513920,
      "url": "https://api.github.com/repos/.../releases/assets/12345"
    }
  ]
}
```

**Два хеша, потому что у них разные задачи.** `sha256` считается по
байтам архива и проверяет целостность скачивания. `contentId` считается
по содержимому — хеш от отсортированных строк «путь пробел sha256» —
и отвечает на вопрос выкладки «менялась ли папка». Без него пришлось бы
полагаться на побайтовую воспроизводимость zip, которую `tar` не
обещает: любая пересборка выглядела бы изменением и гнала бы 262 МБ
вхолостую.

`contentId` лаунчер не читает. Это поле выкладки, живущее в манифесте
потому, что манифест — единственное состояние, общее для машин,
с которых выкладывают.

Разбор `archives` наследует проверки `files`: относительный путь без
`..` и буквы диска, шестьдесят четыре шестнадцатеричных знака в хеше,
адрес только http или https, запрет дубликатов. Дополнительно `dir`
обязан быть одним сегментом пути и присутствовать в `managedDirs`.

## Состояние на диске игрока

`<instance>/.lmpc-pack.json`, рядом с игрой, вне управляемых папок:

```json
{
  "packVersion": 5,
  "archives": {
    "mods": { "sha256": "...", "files": ["mods/create-6.0.10.jar"] },
    "config": { "sha256": "...", "files": ["config/foo.toml"] }
  }
}
```

Имя добавляется в `PROTECTED`, чтобы никакая чистка его не съела.

**Зачем список файлов.** Хеша архива хватает, чтобы понять «версия
та же», но не хватает, чтобы понять «пак цел». Живой сценарий: игрок
удаляет мод, чтобы «убрать лаги», и потом не понимает, почему не
заходит. Проверка существования каждого файла ловит это и чинит молча.

Проверяем только существование, не хеш. Битый джарник поймает не
лаунчер, а краш клиента.
`ponytail: проверка наличия, не содержимого; если битые файлы станут
реальной проблемой — класть в состояние хеши и сверять их`

## Синхронизация

`planSync(manifest, instanceDir, state)` — чистый расчёт, три списка:

- `toInstall` — архивы, у которых хеш не совпал с состоянием либо
  пропал хотя бы один файл из списка
- `toKeep` — совпавшие
- `dirsToWipe` — папки из `managedDirs`, для которых в манифесте нет
  архива: пак от них избавился, значит и с диска они уходят

Пустой `archives` при непустом `managedDirs` — признак сорвавшейся
загрузки, а не команды стереть пак. Ведём себя как сейчас: чистку
пропускаем, причину возвращаем в `skippedDeletion`.

`applySync` — исполнение, в том же порядке, что и сейчас: сначала
получить всё новое, потом удалять.

1. Скачать архивы `toInstall` во временную папку с проверкой `sha256`
   (`downloadAll` это уже умеет, этап `STAGES.PACK`)
2. Для каждого скачанного: удалить содержимое его папки, кроме
   `PROTECTED`, распаковать архив в `instanceDir`, собрать список
   распакованных путей
3. Стереть папки `dirsToWipe`, не трогая `PROTECTED` внутри них
4. Записать новое `.lmpc-pack.json`
5. Удалить временные архивы

Состояние пишется последним. Оборвалась сеть или распаковка — на диске
осталось старое состояние, следующий запуск повторит работу целиком.

Архивы кладём в `<root>/cache/pack/` и удаляем после распаковки: 262 МБ
на диске игрока ради экономии, которой не будет — второй раз тот же
архив не понадобится.

## Распаковка

Берём готовый `unzip` из `src/main/archive.js`: `tar.exe` из состава
Windows, запасной путь — `Expand-Archive`. Архивы содержат путь
от корня инстанса (`mods/foo.jar`), поэтому распаковка идёт прямо
в `instanceDir`, `stripSingleRoot` не нужен.

Список распакованных файлов берём обходом папки после распаковки,
а не разбором zip: обход уже написан, разбор — нет.

## Выкладка

`npm run publish` без аргументов. Настройки — в `launcher/publish.json`,
файл не версионируется, в нём токен:

```json
{
  "repo": "xxxDenthe/minecraft_server_plague",
  "tag": "pack",
  "token": "github_pat_...",
  "dir": "pack-build",
  "server": "host:25565",
  "maxRamMb": 6144
}
```

Ключи командной строки остаются и перебивают файл — они удобны при
отладке. Файла нет — скрипт говорит, что создать и с какими полями.
`launcher/publish.json` уходит в `.gitignore` рядом с
`src/main/distribution.json`: в обоих лежит токен.

Порядок работы:

1. Прочитать настройки, проверить токен (`checkToken` уже есть)
2. Найти релиз по тегу. **Нет — создать**, а не падать: `POST
   /repos/{repo}/releases` с `tag_name` и `draft: false`. Сейчас скрипт
   требует готового релиза, и это половина ручной возни
3. Обойти управляемые папки, посчитать `contentId` каждой
4. Скачать прошлый `pack.json`. Папки с тем же `contentId` не трогать:
   переиспользовать их `url`, `sha256` и `size` из старого манифеста
5. Для изменившихся: собрать zip через `tar`, посчитать `sha256`,
   удалить старый ассет, залить новый
6. Собрать манифест, `packVersion` = прошлый плюс один, проверить его
   собственным `parseManifest`, залить

Сборка архива:

```
tar.exe -c -f <кэш>/mods.zip --format=zip -C <pack-build> mods
```

Тот же `tar.exe`, что уже используется для распаковки. Новых
зависимостей нет.

Файлы из `PROTECTED` в архив не попадают — правило переносится
как есть: иначе лаунчер затрёт игроку настройки.

## Совместимость

Старые манифесты не поддерживаем. Лаунчер собирается заново и
раздаётся заново, сессия ещё не началась, живых установок со старым
паком нет ни одной, кроме двух наших.

Установка со старым паком на диске чинится сама: `.lmpc-pack.json`
отсутствует, значит все архивы считаются неустановленными, папки
чистятся и наполняются заново.

## Ошибки

| Что случилось | Что делаем |
|---|---|
| Релиза с тегом нет при выкладке | Создаём |
| Токену не хватает прав | Текущее сообщение про Contents: Read and write — оставить |
| Архив скачался с неверным хешем | Ошибка загрузки, папка не тронута — `downloadAll` уже так делает |
| `tar` не нашёлся при распаковке | Запасной `Expand-Archive`, уже написан |
| `tar` не нашёлся при выкладке | Падаем с внятным текстом: выкладка идёт на машине владельца, запасной путь тут не окупается |
| Манифест без `archives` | `parseManifest` падает с описанием поля |

## Тесты

Правим существующие, новых файлов минимум:

- `manifest.test.js` — разбор `archives`, отказ на `dir` с путём,
  на `dir` вне `managedDirs`, на дубликате `dir`
- `sync.test.js` — расчёт `toInstall` по хешу и по пропавшему файлу;
  `dirsToWipe`; отказ чистить при пустом `archives`; `PROTECTED`
  переживает установку
- новый `state.test.js` — чтение и запись `.lmpc-pack.json`;
  отсутствующий и битый файл читаются как «ничего не установлено»
- `publish` — проверяем чистую часть: `contentId` и решение
  «переиспользовать или залить». Сеть и `tar` не мокаем

## Что осознанно не делаем

- Дельта-обновления внутри архива. 262 МБ качаются две минуты,
  моды меняются редко
- Кэш архивов между запусками
- Поддержка не-Windows на стороне выкладки
- Зеркала и резервный хостинг
