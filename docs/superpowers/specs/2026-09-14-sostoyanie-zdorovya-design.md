# Интерфейс «Состояние здоровья»

Дизайн клиентского интерфейса, которым игрок осматривает сам себя и
соседа. Ревизия 1, 2026-09-14. Подсистема 2 (Игрок), надстройка над уже
закрытой механикой болезни.

Исходное задание владельца — `E:\Downloads\Production prompt — PlagueCore
Health Status GUI.md`; справка по механике, из которой оно выросло, —
`docs/bolezn-mehaniki-dlya-chatgpt.md`.

## 1. Зачем

Болезнь в моде работает полностью, но игрок не видит её ничем, кроме
тускнеющего экрана, значков ванильных эффектов и собственного кашля.
Понять «мне стало хуже или показалось» нельзя, а лечиться вслепую —
не решение, а угадывание.

Интерфейс закрывает эту дыру, **не открывая механику**. Игрок получает
не приборную панель, а ощущения: «кажется, я не в лучшей форме», «в
ногах слабость». Числа заражения, стадии, пороги, коэффициенты и
технические названия эффектов не показываются никогда и никому,
включая Клирика.

Это осмотр, а не диагностика. Критерий качества один: открыв экран
впервые, человек должен подумать «я смотрю на себя», а не «я открыл
меню настроек».

## 2. Границы

**Что делаем.** Клавиша, полный экран, HUD, интерактивная модель тела,
субъективные тексты, журнал событий на сессию, осмотр соседа,
расширенный осмотр у Клирика, искажение интерфейса при одержимости.

**Чего не делаем.** Ни одной новой игровой механики. Ни одного нового
счётчика, стадии, эффекта или источника заражения. Интерфейс только
читает то, что уже посчитал сервер. Второго «менеджера инфекции»
не появляется.

**Чего не трогаем.** `PlayerInfection`, `PlagueSymptoms`, `PlagueCough`,
`InfectionMath` — только читаются. Папка `launcher/` принадлежит второму
участнику: клавиша по умолчанию уезжает туда отдельной задачей
(раздел 12).

## 3. Решения владельца

Приняты 2026-09-14, до начала работы:

| Развилка | Решение |
|---|---|
| Визуальная база экрана | Тёмная панель чумы, как `PlagueMapScreen`, а не бумага записей |
| Модель тела | Живая модель игрока со скином, а не спрайт и не прямоугольники |
| Осмотр соседа | Та же клавиша, глядя на человека; мгновенно, без цены |
| Клавиша по умолчанию | `Y` |
| Положение HUD | Левый верхний угол |
| Искажение интерфейса | Только пока телом правят (`PossessionClient.ведут()`) |

Решение про модель со скином влечёт следствие, которое стоит записать:
модель рисуется **лицом к игроку, без поворота за мышью**. Ванильный
`renderEntityInInventoryFollowsMouse` крутит тело вслед за курсором, и
тогда область руки уезжает из-под самой руки — попасть по ней мышью
нельзя. Берётся `renderEntityInInventoryFollowsAngle` с нулевыми углами.

## 4. Откуда берутся данные

Ключевая находка исследования: **для осмотра себя новая сеть не нужна
вовсе.** Всё уже на клиенте.

| Что | Откуда на клиенте |
|---|---|
| Стадия 0–4 | `PlagueClientAccess.стадия()`, пакет `Stage` приходит при каждой смене |
| Здоровье и его максимум | `mc.player.getHealth()`, `getMaxHealth()` |
| Сытость | `mc.player.getFoodData()` |
| Действующие эффекты | `mc.player.getActiveEffects()` |
| Одержимость | `PossessionClient.ведут()`, `чума()` |
| Класс игрока | `ClassBridge` — вложение `lmpc_classes` синкается с 0.6.0 |
| Жажда | `ThirstBridge` — вложение `ThirstWasTaken` есть и на клиенте, мод сам рисует по нему HUD |

Оба моста уже написаны и уже работают через рефлексию с тихим отказом.
Они становятся публичными и получают по одному методу чтения
(`ClassBridge.класс`, `ThirstBridge.уровень`) вместо того, чтобы
заводить рядом вторую пару таких же мостов. Без `lmpc_classes` Клирика
просто нет, без мода жажды строка жажды не рисуется — ни падения, ни
пустого элемента.

Единственное, чего у клиента нет, — состояние **соседа**. Под него
заводятся два пакета (раздел 9).

```

                         ни одного import net.minecraft, под CorePurityTest

client/HealthHud.java    строка в левом верхнем углу

mc/ClassBridge.java      публичный, +класс()
mc/ThirstBridge.java     публичный, +уровень()

assets/plaguecore/lang/{ru_ru,en_us}.json   все строки интерфейса

```

Ни одной строки видимого текста в Java: `Wellbeing` возвращает ключи,
экран превращает их в `Component.translatable`. Русский заводится сразу,
английский — тем же списком ключей, чтобы архитектура позволяла третий
язык без правки кода.

## 6. `Wellbeing` — система текстов

Ядро проекта не знает о Minecraft, и выбор текста туда ложится целиком:
это чистая функция от нескольких чисел. Значит, он тестируется обычным
JUnit, без запуска игры, и `CorePurityTest` стережёт его чистоту.

**Шкала самочувствия.** Пять ступеней, по стадии болезни:

```
0  здоров            Кажется, я здоров.
1  слегка нехорошо   Сегодня я чувствую себя немного хуже.
2  нехорошо          Мне что-то нехорошо.
3  плохо             Я чувствую себя очень плохо.
4  край              Со мной происходит что-то ужасное.
```

Ступень берётся от стадии один в один. Это намеренно: вводить свою
шкалу поверх серверной значило бы завести вторую механику, а её
запрещает раздел 2.

**Части тела.** Шесть кликабельных областей, четыре текстовых группы:
голова, туловище, руки, ноги. Левая и правая рука говорят одно и то же —
болезнь не различает стороны, а притворяться, что различает, значит
врать игроку. Симптомы распределены художественно, но только те, что
реально есть в механике:

| Часть | Чем отзывается | Из какой настоящей механики |
|---|---|---|
| Голова | усталость, тяжесть, потеря сосредоточенности, потеря контроля | тошнота приступа, одержимость стадии 4 |
| Туловище | недомогание, тяжесть, дыхание, кашель | кашель, вдох спор, урон стадии 4 |
| Руки | слабость, бессилие, тяжесть движений | `WEAKNESS`, `DIG_SLOWDOWN` |
| Ноги | слабость, тяжесть, плохой контроль | замедление приступа |

Итого 4 группы × 5 ступеней = 20 ключей на себя, столько же на соседа,
плюс добавочная строка Клирику в обоих случаях.

**Голод и жажда** описываются своими короткими шкалами по уровню
сытости и жажды, без коэффициентов болезни: «есть хочется чаще
обычного», «всё время хочется пить».

**Эффекты** переводятся в ощущения по таблице «идентификатор эффекта →
ключ», без названия и без уровня:

```
minecraft:weakness        Руки кажутся тяжелее обычного.
minecraft:mining_fatigue  Работа даётся тяжелее.
minecraft:slowness        Мне тяжело двигаться.
minecraft:water_breathing Такое чувство, что я могу долго не дышать.
minecraft:speed           Я двигаюсь быстрее обычного.
...
```

Неизвестный эффект не показывается вовсе — лучше промолчать, чем
выдать «Effect 47». Длительность не показывается: она техническая.

## 7. Экран

Панель 248 × 166. **Оформление переделано 2026-09-16** по решению
владельца: вместо плоской заливки `fill()` — «полевой лазарет»,
просмолённый кожаный планшет с латунными уголками, строчкой по краю
и двумя утопленными врезками: под фигуру и под текст. Панель приходит
готовой картинкой `textures/gui/health_panel.png`; рисует её
`tools/lazaret-gfx/графика.py` — тем же приёмом, что и графику записей
архивов: четыре тона, дизеринг по Байеру, ни одного плавного перехода.

Палитра ушла из серой в тёплую костяную — на кожаном поле серый
мертвеет: текст `0xFFE2DDCE`, тусклый `0xFF9B9280`, латунь `0xFF8A7241`,
тёмная латунь `0xFF4E4024`, кость `0xFFD9CCA6`. Никакого неона, стекла
и свечения по-прежнему нет.

```
╔═■═══════════════════════════════════■═╗
║ СОСТОЯНИЕ ЗДОРОВЬЯ         [▣][▣][▣][▣]║
║ ────────────────────────────────────── ║
║ ┌────────┐  САМОЧУВСТВИЕ              ║
║ │        │  ────                      ║
║ │ модель │  Кажется, я не в лучшей    ║
║ │        │  форме.                    ║
║ │        │  ──────────────────────    ║
║ │        │  ███████░░░   14 / 20      ║
║ │        │  ◔ Есть хочется чаще       ║
║ └────────┘  ◍ Всё время хочется пить  ║
╚═■═══════════════════════════════════■═╝
```

**Геометрия панели жёсткая и продублирована в двух местах** — в
`HealthScreen.java` и в генераторе картинки. Врезка под модель:
`МОДЕЛЬ_X = 12`, `МОДЕЛЬ_Y = 34`, `64 × 122`, масштаб фигуры `40`.
Правая колонка начинается на `+88` и занимает `148` пикселей. Разойдутся
эти числа со скриптом — рамки уедут с мест, и это будет видно сразу.

**Шрифт заголовков.** Заголовок экрана и названия разделов набраны
своим шрифтом `plaguecore:lazaret` — узкая прописная антиква в семь
пикселей, капительная (строчные ячейки несут ту же картинку, что и
прописные). Тело текста осталось ванильным: на мелком кегле оно
читается лучше, и это намеренно. Лист знаков рисует тот же скрипт.

**Анимации.** Все считаются от `Util.getMillis()`, а не от тиков: тики
рвутся на лагах, а экран паузу не ставит и обязан идти ровно. Каждый
сдвиг нормирован на длительность кадра, поэтому скорость не зависит
от числа кадров в секунду.

| Что | Как |
|---|---|
| Открытие экрана | панель за 200 мс проявляется и подтягивается на семь пикселей вверх |
| Смена вкладки | содержимое правой врезки выезжает со сдвигом и проявляется за 150 мс |
| Полоз вкладок | латунная черта под открытой вкладкой доезжает, а не перепрыгивает |
| Шкала здоровья | заполнение догоняет значение, светлый хвост потери отстаёт втрое |
| Пульс шкалы | тем чаще и заметнее, чем меньше сил: от 1200 мс на полном до 260 мс на краю |
| Дыхание гнили | кайма по краю панели дышит тем глубже и чаще, чем выше ступень |

**Модель слева всегда**, во всех вкладках. Вкладки меняют только правую
панель — экран не перелистывается на новую страницу, как и требует
задание. Клик по части тела сам переключает панель на вкладку «Тело».

**Вкладки** — четыре пиксельных значка в шапке, каждый на утопленной
плашке 16 × 16; у открытой кайма латунная, под курсором — костяная,
у закрытых значок притушен. **Подписи из шапки убраны 2026-09-16:**
четыре русских слова рядом с заголовком в 248 пикселей не помещались
и жили ужатым до 0.6 шрифтом, а пиксельный шрифт в нецелом масштабе
разваливается. Вместо этого имя открытого раздела стоит заголовком
над его же содержимым в правой врезке, а имя закрытой вкладки
показывается всплывающей подсказкой при наведении.

| Вкладка | Что в правой панели |
|---|---|
| Состояние | общее самочувствие, шкала жизненных сил и число, голод, жажда |
| Тело | описание выбранной части; пока не выбрана — подсказка «нажми на часть тела» |
| Ощущения | действующие эффекты человеческими словами |
| Память | журнал последних событий |

**Показатели прижаты к низу врезки**, а не идут следом за текстом.
Текст самочувствия бывает длиной от одной строки до четырёх: если
вешать шкалу за ним, она пляшет по высоте от ступени к ступени, а под
ней зияет пустая треть панели. Прижатый низ стоит на месте всегда.

**Шкала жизненных сил вместо сердец.** Решение владельца 2026-09-16:
ряд ванильных сердец заменён своей полосой 100 × 9 — жёлоб, три слоя
крови (светлый верх, тело, тёмный низ), светлая ведущая кромка на срезе
заполнения и насечки через каждые два здоровья, чтобы полоса осталась
считаемой ровно так же, как считались сердца. Рядом то же компактное
`14 / 20`.

Полоса живая: заполнение догоняет значение, а не прыгает; после урона
светлый хвост потери отстаёт втрое и видно ровно то, что только что
сняли; вся полоса пульсирует тем чаще, чем меньше сил.

Максимум учитывается как есть: постоянная потеря за смерти и временный
штраф стадии оба уже сидят в `getMaxHealth()`, поэтому отдельно считать
нечего и объяснять причину не нужно — игрок видит, что полоса стала
короче, и всё.

**Попадание по частям тела.** Модель рисуется в известном
прямоугольнике; ноги, туловище, голова и руки занимают в нём
фиксированные доли по пропорциям модели игрока (ноги 0–0.375 высоты,
туловище 0.375–0.75, голова 0.75–1.0; руки — полосы по бокам
туловища). Числа подкручиваются на глаз при первой живой проверке.

**Наведение** рисует пиксельные уголки вокруг части, а не заливку:
подсветить кусок 3D-модели поверх скина нечем, а уголки читаются и
не портят картинку. Уголки белые (`0xFFFFFFFF`) и одинаковые у всех
частей, и живут **только под курсором**: выбранная часть уголки не
держит — какая часть выбрана, видно по правой панели. Решение
владельца на живой проверке 2026-09-16.

**Уголки поднимаются над моделью по Z.** Ваниль рисует фигурку на
`z = 50` (`InventoryScreen.renderEntityInInventory`), а `GuiGraphics.fill`
идёт на `z = 0`, поэтому без подъёма рамка уходит за модель и на экране
остаются только те её куски, что торчат мимо силуэта: на живой проверке
2026-09-16 это выглядело как «рамка работает исключительно на руках».
Подъём сделан внутри `уголки()`, чтобы он был у любого вызова.

**Парные части подсвечиваются парой.** Текст у левой и правой руки
один, поэтому и уголки встают сразу на обе руки; то же с ногами.
Иначе человек видит выделенной одну руку и читает описание, которое
говорит про обе, — и не понимает, про какую именно ему рассказывают.

**Экран не ставит игру на паузу** (`isPauseScreen() == false`): сервер
сессионный, пауза там всё равно не работает, а стоять с открытым
экраном в гнили должно быть опасно.

## 8. HUD

Левый верхний угол, одна короткая строка субъективного состояния,
пиксельный шрифт, тёмная подложка. Хотбар, чат и прицел не задевает.
На стадии 0 не рисуется совсем.

Подложка с 2026-09-16 получила ту же отделку, что и планшет осмотра:
тонкая тёмная кайма и латунный засек по левому краю. Строка и экран
должны читаться как одна вещь, а не как два разных интерфейса.

Строка короче экранной: «Мне нехорошо» вместо «Мне что-то нехорошо, и
я не понимаю почему». Чем хуже состояние, тем тревожнее формулировка.

Левый верхний угол в паке занят значками голосового чата. Их положение
проверяется при первой живой сборке; если пересекутся — HUD опускается
на высоту значков, а не переезжает в другой угол.

## 9. Осмотр соседа

Игрок смотрит на другого игрока и жмёт ту же клавишу. Открывается тот
же экран, но чужой: вкладки «Ощущения» и «Память» скрыты — чужих
ощущений и чужой памяти знать неоткуда, а показывать их значило бы
выдать механику.

Два пакета в `PlagueNetwork`:

```java
Look(int сущность)                       клиент → сервер
Impression(int сущность, int впечатление) сервер → клиент
```

`впечатление` — грубая ступень 0–4, та же шкала, что у себя. Сервер
проверяет сам: отправитель и цель в одном мире, расстояние не больше
восьми блоков, цель — игрок. Клиенту здесь не верим по тому же
правилу, что и в админском экране: экран можно открыть подменённым
клиентом.

Тексты чужого осмотра — наблюдения снаружи, не ощущения: «он выглядит
нехорошо», «ему тяжело», не «мне тяжело».

## 10. Клирик

Если `lmpc_classes` установлен и игрок — Клирик, к каждому описанию
добавляется вторая строка: то же самое, но подробнее. Не число, не
процент, не стадия — **лучше замеченный симптом**.

```
Обычный игрок:  Его руки выглядят слабыми.
Клирик:         Его руки выглядят слабыми.
                Он почти не пользуется ими как обычно.
```

Работает и на себе, и на соседе. Без мода классов добавочной строки
просто нет.

## 11. Память

Клиентское кольцо на двенадцать записей. Живёт до выхода из мира и
обнуляется при перезаходе — это прямое требование задания.

Пишется **и когда экран закрыт**: иначе журнал пуст ровно в тот момент,
когда его впервые открывают. Четыре источника событий, все видны
клиенту без новой сети:

| Событие | Как замечено | Запись |
|---|---|---|
| Стадия выросла | пакет `Stage` | Мне стало хуже. |
| Стадия упала | пакет `Stage` | Кажется, мне немного легче. |
| Выпит отвар | окончание использования предмета | Я выпил отвар. |
| Началась или кончилась одержимость | `PossessionClient` | Я не помню, что было только что. |

Время берётся из внутриигровых суток и пишется как `09:31`. Ничего
технического: не «−13 очков», а «после отвара стало легче».

## 12. Клавиша

`key.plaguecore.health`, по умолчанию `Y`, категория — своя, регистрация
через `RegisterKeyMappingsEvent`. Видна и переназначается в стандартных
настройках управления. Нажатие обрабатывается в `ClientTickEvent.Post`
через `consumeClick`.

`Y` свободна во всём паке — проверено по
`launcher/pack-config/config/lmpc-default-options.txt`. Занят только
`Ctrl+Y` (отмена в `mapwright`), и это другой экран.

**Остаётся за границей нашей папки.** Чтобы клавиша доехала до игроков,
в образец настроек нужна строка

```
key_key.plaguecore.health:key.keyboard.y
```

и запись в `KEY_MIGRATIONS` лаунчера — иначе те, кто уже играл, ничего
не получат (разбор — заметка `2026-09-12-posle-pervogo-testa-klavishi-i-drop`).
Обе правки живут в `launcher/`, то есть у второго участника. Задача
передаётся ему заметкой, а не правится из этой сессии.

## 13. Искажение при одержимости

Пока `PossessionClient.ведут()` истинно, экран перестаёт вести себя как
экран. Не глитч и не sci-fi: мрачный пиксельный физический ужас.

- панель дрожит на пиксель-два, вразнобой;
- строки текста сползают и иногда встают не на своё место;
- модель дёргается сама, конечности на миг принимают неправильные позы;
- отдельные элементы ненадолго пропадают;
- поверх интерфейса приходят чужие фразы — `Я ЧУВСТВУЮ — ВЫХОДА НЕТ.`,
  `ПРИЧИНИ ИМ ВРЕД` и несколько других.

Чужие фразы должны читаться как вторжение, а не как подпись UI: другой
цвет, другое место, появляются рывком.

Вне одержимости стадия 4 остаётся мрачной, но читаемой: гниль по краям
панели, приглушённый текст. Дрожь, рывок модели и чужие фразы — только
пока телом правят (см. решения владельца, раздел 3); сама по себе
высокая стадия экран не трясёт. Редкое событие обязано оставаться
редким, иначе через два открытия оно перестанет пугать и начнёт мешать.

## 14. Производительность

Состояние пересчитывается раз в десять тиков, не каждый кадр.
`Component` собираются в момент пересчёта и лежат готовыми — в
`render` не создаётся ни строк, ни объектов. Частиц интерфейс не
порождает вовсе. На TPS не влияет ничем: весь код клиентский.

## 15. Проверки

- JUnit на `Wellbeing`: каждая ступень даёт свой ключ, неизвестный
  эффект даёт пусто, границы шкал не выпадают за массивы;
- `CorePurityTest` — ядро осталось чистым;
- сборка и `runClient`: экран открывается, части тела нажимаются,
  вкладки переключаются, HUD не лезет на хотбар;
- `runServer`: ни один клиентский класс не грузится на выделенном
  сервере (все входы идут через `PlagueClientAccess`, как заведено);
- запуск без `lmpc_classes` — Клирика нет, падения нет;
- запуск без мода жажды — строки жажды нет, падения нет;
- живая проверка состояний 0–4 через `/plague setstage` и одержимости
  через панель мастера игры.

## 16. Открытые вопросы

- Точные доли высоты для попадания по частям тела — подбираются глазом
  при первом запуске, в спеке стоят прикидочные.
- Пересечение HUD со значками голосового чата в левом верхнем углу.
- Звуки: открытие экрана и выбор части тела намечены тихими ванильными
  сэмплами; окончательный подбор — по слуху владельца, а не по спеку.
